# 动画系统设计（拍题动画 + 知识点原语库）

- **日期**：2026-09-17
- **状态**：待评审
- **范围**：动画内核（原语库 / 动画 IR / 渲染器）、拍题链路、知识点侧（探索台 + 示范动画）、内核的移动端硬约束

## 0. 一句话

**AI 不写代码，只出动画 IR。渲染器只有一套，两个来源、两个模式。**

---

## 1. 背景：现状的三个时钟

动画这件事目前在仓库里有三处各写各的，互不知道对方存在：

| 位置 | 实现 | 实际角色 |
|---|---|---|
| `src/engines/animationController.js:67` | `setTimeout` 步进器 | 名义上的动画控制器，但走时机制与渲染脱节 |
| `src/pages/WorkspacePage.jsx:1145` | `setTimeout(tick, 2800)` | **当前真正的播放来源** |
| `src/features/solid-geometry/Canvas3D.jsx:287` | `useFrame` | 唯一的逐帧动画 |

由此产生三个后果：

1. **播放 / 暂停 / 拖进度是三条不同路径**。因为它们分别落在不同的时钟上，无法统一控制。
2. **切屏后动画错乱**。`setTimeout` 在移动端后台会被系统节流，恢复时会出现时间跳变。
3. **`sceneIRValidator.js:544` 的 `validateSceneIR` 闸门存在但未接入生产**。也就是说：「AI 产出 → 校验 → 渲染」这条链路的最后一道关卡目前是摆设。

### 历史教训（必须写进设计，不是背景知识）

`docs/PLAN-parallelepiped.md:166` 记录过一次静默兜底：`createGeometryFromSceneIR` 遇到不认识的类型时**返回默认几何体**。结果是「平行六面体被静默画成了正方体」——用户看到了一张不存在错误的错误的图。

**所以本设计的第一原则是：宁可不出图，绝不静默出一张错图。** 后面所有失败路径都遵守这一条。

### 性能依据（仓库内已有）

`docs/P0-DIAGNOSTIC-REPORT.md:74` 已把下列现象标为「中」影响：

> `Canvas3D` | `useFrame` → `setTransitionTick` | ~20fps（高亮动画期间） | 中

同一份报告的建议是「改用 `ref + invalidate()` 而非 `setState`」。本设计直接采纳为硬约束（见 §6.1）。

## 2. 决策记录

| 编号 | 决策 | 结论 |
|---|---|---|
| D1 | 动画生成路线 | **分层方案**：知识点侧离线（AI 起草 IR → 过闸门 → 人签字 → 固化）；拍题侧运行时 IR 编排。**不做运行时 AI 写代码 + 沙箱** |
| D2 | 拍题动画生成时机 | **两段式**：拍完立即出静态图 + 步骤；用户点「播放」才生成动画 |
| D3 | 知识点侧的「详细」 | **探索台 + 示范动画** 两者都要 |
| D4 | 移动端手势 | 按模式分派，不做动态仲裁 |
| D5 | 知识点侧离线可用 | 内核不得假设网络可用；v1 只交付在线路径，预置能力预留 |
| D6 | 拍题原图留存 | **不持久化原图**，OCR 完成后只保留文本与派生 IR（未成年人个人信息） |
| D7 | 动画缓存 | 跨用户共享 + 反馈达阈值时作废重生成 |
| D8 | 坐标来源 | **AI 永远只出 IR，代码永远由人写**。遵守 `scene-ir-core` 的 Enforcement 第 4 条（AI-generated coordinates → Forbidden），不为任何一侧开例外 |

### D1 的理由（为什么不要沙箱）

风险的归属要分清：

- **正确性风险**（画错公式）→ 免责声明 + 用户反馈可以兜。这一层用户已接受。
- **执行安全风险**（拍题 OCR 文本进 AI，图片里可藏对抗性文字 → 生成的代码在自家域名下执行）→ **免责声明兜不住**。

沙箱（无网络 Worker / iframe + 仅暴露绘图 API + CSP + 执行超时 + 输出审核）能解决执行安全，但要单独排期，且会让拍题链路的唯一安全屏障依赖一个尚未存在的组件。

而「AI 只出结构化 IR」这条路，**根本没引入执行面**。最强的情况是「生成了一个错的动画」，不可能变成「执行任意代码」。代价是表达力受原语库限制——但这个代价只落在知识点侧（需要精雕细琢），不落在拍题侧（题目范围是收口的，瓶颈是组合覆盖度而非表达力上限）。

所以拆成两条：

- **拍题侧**：运行时 IR。安全边界由「无代码执行面 + 闸门」提供。
- **知识点侧**：离线。AI 只生成 **IR 草稿**，同样过闸门，再由人签字固化进仓库；新原语（代码）由人写。运行时零 AI 调用、零执行面。

两边都遵守同一条铁律：**AI 永远只出 IR，代码永远由人写**（D8）。

## 3. 架构

```
① 动画原语库（手写，可信）
   每个原语 = 一个渲染组件 + 一份「可动画槽位」声明 + 一份派生量声明

② 动画 IR，两个来源
   来源1【运行时】AI 生成 → 必须过闸门 → 渲染
   来源2【离线】AI 起草或人手写 → 过同一套闸门 → 人签字 → 进仓库 → 渲染

③ 可信渲染器（写一次，两侧共用）
   时间轴模式：播放 IR 的 tracks（关键帧插值 + 缓动 + 播放/暂停/拖进度/变速）
   实时模式：直接绑 params，无时间轴 —— 这就是「探索台」
```

### 3.1 原语契约

槽位声明就是 **AI 的全部可动空间**。AI 改不了槽位声明之外的东西，也改不了派生量。

```js
export const capacitorPrimitive = {
  id: 'capacitor',
  // AI 唯一可写的部分
  slots: {
    d: { type: 'number', min: 0.5, max: 5,   unit: 'mm' },  // 板间距
    S: { type: 'number', min: 1,   max: 100, unit: 'cm²' }, // 板面积
    U: { type: 'number', min: 0,   max: 50,  unit: 'V' },   // 电压
  },
  // 只读派生量：由引擎计算，AI 不可写
  derived: {
    C: 'EPS0 * S / d',
    E: 'U / d',
  },
  Component: Capacitor,
}
```

`derived` 是关键设计：**物理量之间的耦合不由 AI 负责**。AI 拖 `d`，`C` 由引擎按公式算出来。这一刀砍掉了整类「公式对但量纲错」「C 变了但 E 没跟着变」的错误。

### 3.2 动画 IR

```js
{
  scene: 'capacitor',
  params: { d: 2, S: 10, U: 12 },
  duration: 4,
  tracks: [
    { slot: 'd', keys: [{ t: 0, v: 2 }, { t: 1.5, v: 1, ease: 'easeInOut' }] },
  ],
  overlays: [
    { kind: 'label', text: 'C = ε₀S/d', anchor: 'plate-gap', from: 0.5, to: 3 },
  ],
}
```

`overlays` 只能放在**原语已声明的锚点**上（如 `plate-gap`）。锚点集合随原语走，AI 无法凭空指定位置。

### 3.3 渲染器的两个模式

| 模式 | 输入 | 用途 | 时钟 |
|---|---|---|---|
| 时间轴模式 | IR 的 `tracks` | 拍题动画、知识点示范动画 | 内部唯一时钟 |
| 实时模式 | 直接改 `params` | 知识点探索台 | 无时钟，改参数即重绘 |

两个模式共用同一套原语组件与同一个采样/派生量管道。**探索台不需要新引擎**——它就是渲染器的实时模式；示范动画则是人手写（或 AI 起草后过闸门）的一条 IR 跑在时间轴模式上，相当于把探索台的正确操作路径录了一遍。两者天然一致，不会出现「探索台讲的和动画讲的不一样」。

### 3.4 与 scene-ir-core 的一致性

本设计是 `scene-ir-core` 的延伸，不是例外。逐条对照：

| scene-ir-core 的要求 | 本设计的对应 |
|---|---|
| ALL geometry must be derived from SceneIR，NO exceptions | 动画 IR 是 SceneIR 的**时间维扩展**：`scene` + `params` 定位到静态图，`tracks` 描述它随时间的演化。渲染层仍然只认 IR |
| AI must NEVER directly control visuals | AI 只写 `tracks` / `overlays` 的声明式数据，且只能落在原语**已声明的槽位与锚点**内。它无法指定任意坐标 |
| AI-generated coordinates reaching the renderer unchecked | 坐标由原语组件的实现算出。AI 改的是参数，不是坐标 |
| labels derived from ID map only | `overlays[].anchor` 必须是原语声明的锚点名，AI 不能自造位置 |
| deterministic output required | 渲染器是纯函数：同一 IR + 同一 `t` 永远画出同一帧（`sampleAnimationIR` 可单测即为此） |
| 校验不通过 → **不画**，并说明原因 | §4.3 的失败路径表逐条落实，且明确禁止「静默退回一个随便画的动画」 |
| AI 生成组件代码 | **不做**（D8）。代码由人写 |

## 4. 拍题链路

### 4.1 主链路

```
拍照
 → OCR（已有 api/ai/ocr.js）
 → 拆小题（已有 subQuestions.js）→ N 个小题
 ── 第一段：便宜、即时 ────────────────────────────
 → 每题：problemParser → 候选场景描述 → validateSceneIR → SceneIR（静态图）
 → 每题：ExplainIR 步骤理解
 → 渲染成 N 张卡片（一题一卡片，卡内横滑切小题）
 ── 第二段：用户点「播放」才发生 ───────────────────
 → AI 生成动画 IR（输入 = 该小题的 SceneIR + ExplainIR，不是原始 OCR 文本）
 → validateAnimationIR → 通过才渲染；不通过 → 不画 + 说明原因
```

### 4.2 两个刻意的设计

**① 动画生成器的输入是「已校验的 SceneIR + ExplainIR」，不是 OCR 原文。**

OCR 原文只喂第一段。这不是万无一失的隔离，但它把攻击面从「两段」收窄到「一段」，并且第二段的输出受闸门约束——即使注入成功，能得到的也只是一条结构非法的 IR，会被闸门拦下。

> **前置依赖（必须与 §4 同期交付）**：上面这句安全论证成立的条件是 `validateSceneIR` 真的在链路上。而 §1 已指出，`sceneIRValidator.js:544` 的闸门目前**未接入生产**。因此「把 `validateSceneIR` 接入第一段」是本设计的**前置依赖**，不是可选项。若不做，则 §4.2 的安全边界退化为「只有第二道闸门」，本设计需重新评审。
>
> 另注意区分两个闸门，它们不是同一个东西：
> - `validateSceneIR`（已存在，需接入）——管第一段的**静态图**。
> - `validateAnimationIR`（本设计新增）——管第二段的**动画 IR**。

**② 校验两道，第二道是物理复算。**

- **第一道：结构校验**（`validateAnimationIR`）
  - 原语 `id` 在白名单内？
  - `params` 每个字段的类型 / 范围与槽位声明一致？
  - `tracks[].slot` 在原型声明的槽位中存在？
  - `overlays[].anchor` 在原型声明的锚点中存在？
  - `expr` 只使用白名单运算符 / 函数 / `params` 变量。
  - **表达式必须是自己的安全求值器，禁止 `eval` / `new Function`。**

  `scene-ir-core` 要求校验至少覆盖 结构 / 数值 / 退化 / 声明 四类，动画 IR 的对应关系：

  | 类别 | 动画 IR 上的含义 |
  |---|---|
  | 结构 | 原语与槽位 / 锚点白名单；`tracks` / `overlays` 字段完备 |
  | 数值 | `params` 落在声明范围内；`derived` 量纲一致 |
  | 退化 | 时长为 0；关键帧时间非严格单调；引用了不存在的槽位 / 锚点 |
  | 声明 | `derived` 公式与 `tracks` 采样结果一致（即第二道闸门） |

- **第二道：物理复算**
  - 把 `tracks` 的表达式按时间采样实际算一遍，与 `derived` 的定性关系比对。
  - 例：`d` 加倍则 `C` 必须减半；`U` 增大则 `E` 必须增大。
  - 不一致 → reject。

这道闸门才是真正兜住「画错」的。免责声明是它的补充，不是它的替代。

### 4.3 失败与降级

| 失败情形 | 处理 |
|---|---|
| 动画 IR 生成返回不可解析内容 | 不画。保留静态图与步骤，播放按钮降级为「暂不支持动画」+ 一键反馈 |
| 结构校验不通过 | 同上，并记录 reject 原因（用于迭代 prompt 与原语覆盖度） |
| 物理复算不一致 | 同上，记录不一致的具体量（这是最有价值的回归数据） |
| 静态图（第一段）失败 | 走现有的 `PLAN-parallelepiped.md` 所定义的链路处理，本设计不改 |

**统一原则：任何一支失败都退回到「静态图 + 步骤」，绝不静默退回一个随便画的动画。**

### 4.4 成本与缓存

- 每次点「播放」= 1 次 AI 调用。
- 缓存 key = 小题文本归一化 + 参数指纹。
- 缓存放 **IndexedDB**：同题第二次点播放，连网络请求都不需要。
- 缓存**跨用户共享**：同一道题第二个学生点播放是 0 成本。
- 跨用户共享的副作用是错误答案会被复制传播，因此配一条**作废机制**，落地方式定死如下（不预设阈值数字）：
  - **反馈入口**：播放器上的「这画得不对」按钮。与 §4.3 的降级反馈**共用同一个入口**，避免用户面对两个功能相同、名字不同的反馈按钮。
  - **计数与阈值**：按缓存条目独立计数，阈值**可配置**（运营可调）。初值待首批真实反馈数据出来后标定——本设计不预设数字，预设等于瞎猜。
  - **作废动作**：**先记日志，再作废**。条目进入 `invalidated` 状态而非直接删除，保留原 IR 与拒绝原因，以便复盘「错在哪」。
  - **可回滚**：重新生成写为新版本，旧版本保留；若新版本反而更差，能切回旧版本。

### 4.5 交互

- 一题一卡片，卡内横滑切小题，每小题各带播放器。
- 第一段沿用现有 `solve-stream` 链路不改，只把结果按小题分桶。

## 5. 知识点侧

### 5.1 两种形态

- **探索台（实时模式）**：学生拖 `d`、`S`、`U`，实时看 `C`、`E` 变化，配套读数表与公式面板。AI 成本近零（不按题生成）。
- **示范动画（时间轴模式）**：人手写的一条 IR，把该知识点的标准主线演示一遍。

### 5.2 离线管线

```
AI 起草 IR → 离线过同一套闸门 → 人签字 → 固化进仓库
原语库不够用时：由人写新原语（AI 不写代码）
```

- 运行时零 AI 调用、零执行面。
- **AI 不写代码**：它的产出永远是 IR。原语是「可信层」，由人手写——这样「可信」二字在两侧含义一致。
- 「人审在环」的含义是**离线过闸门 + 人签字**，不是「人可以豁免闸门」。
- 表达力缺口由**人补原语**解决：补一个新原语（惠及拍题侧），或为该知识点手写一条专属 IR。**不靠放开 AI 的权限解决。**
- 知识点侧**无网可用**：IR 可随包发布或首启动下载。v1 只交付在线路径，但内核不得假设网络可用（D5）。
- 教材例题用于补充知识点，作为知识点页下挂的 1–2 道例题动画。

## 6. 内核的移动端硬约束

主要用户在手机端，所以内核的默认配置必须是**移动端优先，桌面是增强**。以下四条写进本 spec，因为它们约束的是内核代码本身，不是 UI。

### 6.1 时钟收敛

现状三个时钟（§1）合并成一个：

- 渲染器内部唯一时钟，由 `useFrame` 的 `delta` 累加驱动。
- `animationController` 从「走时器」**降级为纯函数解析器**：
  `sampleAnimationIR(ir, t) → { params, overlays }`，无状态、无定时器、可单测。
- 播放 / 暂停 / 拖进度条 = 改 `time` 的值，不启动任何定时器。于是 `WorkspacePage.jsx:1145` 的 `setTimeout(tick, 2800)` 特例自然消失，**播放和拖拽变成同一件事**。
- **抗后台节流**：`delta` 取 `performance.now()` 差值（而不是计 `setTimeout` 调用次数），再叠加 `visibilitychange` 暂停。因为是 delta 累加，系统节流最多让动画「走慢」，不会「瞬跳」；恢复时把基准时间重设为 `now`，不补帧。
- **逐帧不经过 React 状态**：按 `P0-DIAGNOSTIC-REPORT.md:74` 的建议，逐帧数据走 `ref + invalidate()`，不用 `setState`。这直接消除了那份报告里 ~20 次/秒的 re-render，也顺带消除了「`useFrame` 里 setState」这个结构性反模式。

### 6.2 手势按模式分派

冲突点：卡片横滑是水平拖，3D 旋转是任意方向拖，同一次触摸里抢指针。规则定死：

| 模式 | 指针归属 |
|---|---|
| 动画播放态 | 3D 区 `touch-action: none` 禁旋转，指针归横滑；切小题亦可用底部显式按钮 |
| 探索台态 | 无横滑，指针归旋转与参数拖拽 |

**不做动态仲裁。** 手势的「智能仲裁」在移动端几乎总是退化成误操作。同一时刻只让一个区域需要指针。

### 6.3 性能预算与降级

- **预算值靠真机标定，方法固定**：固定基准场景 + 递增原语实例数，在低 / 中 / 高三档机型各测一次，取 30fps 拐点作为实例上限。标定脚本进仓库、可复跑——因为预算会随原语实现变化，不能写成一次性数字。
- **逐帧零分配**：`sampleAnimationIR` 复用预分配对象；Three 侧复用 `Vector3` / `Matrix4`。
- **移动端默认渲染档**：`dpr ≤ 2`（低端 1.5）、关闭阴影与后处理、`antialias` 按设备能力。
- **降级梯度**（由渲染器统一实现，场景作者不用管）：
  满档 → 降 dpr → 关后处理 → 降到 30fps → **退静态图**。
  最后一档零成本，因为两段式天然已经有静态图。
- **降级判据用连续掉帧，不用单帧**，避免误降级。

### 6.4 包体与内存

- three 相关代码动态 `import`，只在拍题 / 知识点页加载，不进首页。
- 内存里只保留当前卡片的采样结果；动画 IR 缓存落 IndexedDB（§4.4）。
- 知识点探索台与示范动画的 IR 可随包或首启动下载 → 知识点侧无网可用；**拍题必须联网**。

## 7. 拆分出去的文档

`docs/MOBILE-APP-设计.md`（待建）负责：打包方案选型、登录与账号、支付、ICP / 备案、隐私合规、账号注销、内容审核、商店材料。

本 spec 对它的**唯一职责**是钉住一个不变量：

> **内核禁止依赖 App 独有能力**——原生推送、原生相机 SDK 特性、设备 ID、App 内支付回调。

因为 Web 先上、App 后上（上架时间线由合规审批驱动，与代码解耦）。内核一旦依赖了这些能力，Web 端就跑不起来。

### 关于 D6（拍题原图不持久化）

这条虽然形式上属于合规，但它改的是**后端存储**，必须现在写：

- 拍照会拍进学生姓名、学校、手写笔迹，属未成年人个人信息。
- 策略：OCR 完成后服务端不保留原图，只保留 OCR 文本与派生 IR。
- 若产品上需要「回看原图」，则与 D6 冲突，需重新决策——本 spec 按「不保留」编写。

## 8. 非目标

明确不做的事，避免实现时反复：

1. **不做运行时 AI 写代码 + 沙箱**。理由见 §2 D1。
2. **不做手势动态仲裁**。理由见 §6.2。
3. **v1 不做 App**，也不把任何 App 独有能力引入内核。
4. **不追求拍题侧的表达力上限**。拍题侧的目标是「当场能出图、且不出错图」，不是「什么题都能画得漂亮」。表达力缺口由持续加原语填补。
5. **不重构静态图链路**（`problemParser` / `sceneIRBuilder` / `sceneIRTemplate` / `solve-stream`）。本设计在其之上加动画层，不改其内部。
6. **不让 AI 写代码，任何一侧都不**（D8）。这是不违反 `scene-ir-core` 的前提，也是 §3.4 那张对照表能成立的原因。
7. **不把闸门做成可跳过的开关**。不存在「已审核所以跳过校验」的路径——离线来源照样过闸门，人审是**加在**闸门之后的签字，不是替代它。

## 9. 验收标准

### 9.1 可测的断言

- `sampleAnimationIR(ir, t)` 是纯函数：同一 `(ir, t)` 多次调用结果恒等，且不触碰定时器、DOM、全局状态。
- `validateAnimationIR` 对以下输入必须 reject：白名单外的原语 id、槽位范围外的参数、引用不存在槽位/锚点的 track、含 `eval` 或非白名单函数的 `expr`。
- 物理复算闸门对「`d` 加倍但 `C` 未减半」的 IR 必须 reject。
- 任意一支失败路径下，渲染结果必须等于「静态图 + 步骤」，且播放按钮为降级态——**不得出现任何自动生成的替代动画**。
- 动画缓存命中时，第二次播放的 AI 调用次数为 0。
- **渲染器不存在绕过闸门的入口**：`validateAnimationIR` 是到达渲染器的唯一通路，**离线来源也必须走它**（D8 / §8.7）。
- 每个原语必须同时声明 `slots`、`derived`、锚点三者，缺任一者不得注册（锚点缺失会让 `overlays` 失去合法落点）。
- 仓库内不存在任何由 AI 写出的原语代码（D8）。

### 9.2 测试落点

- `src/engines/__tests__/` 下沿用现有测试风格（参考 `sceneIR-geometry.test.js` 的 `auditSceneIR` / `auditGeometry` 做法）。
- 引擎层（纯逻辑）单测覆盖：`sampleAnimationIR`、`validateAnimationIR`、表达式安全求值器、物理复算。
- 每个原语至少 1 个测试用例；每种失败路径至少 1 个用例。
- 视觉与手势在三端（Desktop / Tablet / Mobile）各查一遍，深色模式单独查。

### 9.3 回归清单

- 移动端三端 + 深色模式。
- 切屏 / 锁屏 30s 后恢复，动画时间轴不跳变。
- 降级梯度在低端机上可被触发且不闪退。

## 10. 风险与取舍

| 风险 | 取舍 |
|---|---|
| 原语库覆盖度不足，拍题侧画不出 | 接受。缺口表现为「暂不支持动画」（有静态图兜底），不表现为错图。按 reject 日志持续补原语 |
| 跨用户缓存传播错误答案 | 由 D7 的反馈阈值作废机制兜。成本上仍显著划算 |
| 知识点侧人力（人审 + 写原语）是瓶颈 | 接受。表达力缺口不再由「放开 AI 权限」补偿（D8），只能靠人补原语；知识点数量有限，可控 |
| 拍题动画需要联网 | 接受。知识点侧离线已覆盖「无网也想学」的主场景 |
| OCR 原文中的对抗性文本进入第一段 | 第一段是已有链路、且其输出受 `validateSceneIR` 约束。第二段已被隔离在外，最坏情形是结构非法 IR 被闸门拦下 |
