# 协作约定（给 AI 助手）

> 项目已转为个人自用工具。以下是接手时必读的边界。

## 必读顺序

1. `README.md` —— 项目是什么、怎么跑
2. `docs/task-cards.md` —— 当前该做什么、怎么算做完
3. `docs/DECISIONS.md` —— 为什么是现在这个样子（含踩过的坑）

## 硬性边界

- **不做计划外的功能**。新想法先补进 `task-cards.md` 再排期
- **一次只做一张任务卡**，做完跑 `npm test` + `npm run build` 才进下一张
- 删除类操作前先备份到 `%TEMP%`，删除后立即验证
- 涉及远程分支、默认分支、推送的操作，**命令先列出再执行**
- 不读、不复制 `.env.local`
- 人物实例与名言不得凭记忆生成，必须联网核实权威来源（见 DECISIONS D4）

## 什么活可以放心交给 AI

- 按任务卡执行明确的代码改动
- 跑测试、构建、定位报错
- 写文档、整理结构、核对引用
- 检索并核实公开信息（须给出来源链接）

## 什么活必须人来定

- 产品方向与功能取舍
- 素材内容的事实确认（AI 给草稿与来源，人做最后判断）
- 任何对外操作（推送、改远程设置、发布）
- 涉及未成年人个人信息的内容

## 验收方式

不看"代码写完了"，只看三件事：

1. 测试与构建的实际输出（贴原始结果，不转述）
2. 功能能否按任务卡的验收标准跑通
3. 有没有引入任务卡之外的变化

## 已知的坑

- 本机 `git` 启动本身约 2 秒，别误判成仓库过大
- Git Bash 里给 git 传路径要用 `C:/...`，`/c/...` 会被误解析
- 含特殊字符的文件名删不掉时，先 `mv` 改成安全名字
- PowerShell 工具偶尔整体起不来，改用 Python 标准库兜底
