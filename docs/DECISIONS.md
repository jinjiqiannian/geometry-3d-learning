## D1 · 项目转为个人自用工具（2026-11-23）

**背景**：v1.x 做了 3.5 个月、194 次提交、约 4.4 万行代码，已上线但零用户。
没有推广过，所以"没人用"和"没人知道"无法区分。

**决定**：不再做面向公众的商业产品，转为个人自用学习工具。

**取舍**：
- 放弃：账号体系、订阅、支付、反馈后台、服务端、多用户
- 保留：解题引擎、3D 可视化、知识讲解
- 后果：拍照 OCR 随服务端一并移除，只剩打字输入

**理由**：自用工具不需要验证他人需求，判断标准从"有没有人要"变成"自己用着顺不顺"，
这是一个可以被真实使用检验的标准。

## D2 · 技术路线：Capacitor 套壳，安卓先行（2026-11-23）

**决定**：用 Capacitor 把现有 React 构建产物打包成安卓 App。

**理由**：现有代码是 React + Vite，Capacitor 在 App 内嵌系统 WebView，
通过桥接层暴露原生能力，**前端代码几乎不用改**。React Native 需要重写 UI，
且 Three.js 要换实现，3D 部分基本报废；Flutter 等于完全重写。

**iOS 暂不做**：打包必须有 macOS + Xcode，本机是 Windows，没有正规绕过途径。

## D3 · 语文素材不做推送，只放首页（2026-11-23）

**决定**：取消每日定时推送，改为首页展示 + 手动换一批。

**理由**：用户打开 App 的频率远高于每天一次，固定只给一条会让内容显得很少；
推送还需要通知插件、系统闹钟注册与后台权限适配，而收益不明确。

**副作用**：省掉了整个通知层，P1 工作量减少约一半。

## D4 · 人物实例与名言必须联网核实（2026-11-23）

**决定**：所有人物事迹与引语必须找到 A 级权威来源，否则不入库。

**理由**：AI 生成人物事迹会编造史实，而作文里写错事实比不写更糟；
网络上的"名人名言"伪托比例极高，被阅卷老师认出反而扣分。

**执行标准**：
- A 级：新华社、人民日报、央视、政府网、教育部、两院官网、正式出版传记年谱
- C 级（百科、知乎、公众号、素材网站）只能当检索线索，不作依据
- 每条素材存 `sources[]` 与 `verified`，无来源的标记 false 且不上首页
- 联网不可用时暂停事实性内容生产，不硬写

## D5 · 英语 AI 调用必须带缓存（2026-11-23）

**决定**：精讲结果写 localStorage；生词提取与精讲合并为同一次请求。

**理由**：复习时会反复看同一篇材料，没有缓存等于每次重复付费；
分两次请求也会让成本翻倍。Key 只存本机，绝不进仓库。

## 坑 · 判断分支是否有独有工作，不能只看提交数（2026-11-23）

`git rev-list --count A..B` 显示 `feature/geometry-engine` 有 44 个独有提交，
看起来像一批没合并的工作。实际上 9 月改写历史时 `git rebase` 重放了提交，
**内容没变但哈希全变**，git 按哈希判断，于是把旧哈希全部算成"独有"。

**正确做法**：
```bash
git log --cherry-pick --right-only --oneline A...B   # 按补丁内容去重
git ls-tree -r --name-only B > /tmp/b.txt            # 再用文件树交叉验证
```
实测该分支独有文件只有 4 个垃圾文件，无任何独有代码，可整体废弃。

## 坑 · `git filter-repo` 在本机不可用（2026-09）

它会清空对象库（`in-pack: 0`），导致 HEAD、分支、远程全部失效。
当时靠事前 89 MB 完整备份才恢复。**不要在本机再用它**；
移除纯提交用 `git rebase --onto` 即可。

## 坑 · `.gitignore` 的 `archive/` 规则匹配任意层级（2026-09）

不带前导斜杠的 `archive/` 会连带忽略 `.claude/archive/`。
自用化后已改为不跟踪 AI 工作目录，无需再写否定规则；
但**以后若要在项目内建 `archive` 目录，必须写成 `/archive/`**。
